# ScombZ Login Helper

芝浦工業大学の **ScombZへの自動ログイン** を補助する、Chromium（Chrome・Edge）/ Firefox向け拡張機能です。ScombApp Mobile APIでWeb SESSIONを取得するため、ScombZログインにTOTPは不要です。

従来のADFS自動ログイン・SHA-256 TOTP生成機能も利用できますが、初期状態では無効です。詳細な使い方は下部の折りたたみ欄を参照してください。


## 使い方：ScombZ自動ログイン

1. 拡張機能をブラウザーに読み込み、設定を開きます。
2. 「利用前の確認」を読み、同意して開始します。
3. 大学ユーザー名（学番）と大学パスワードを入力し、**ScombApp APIでログインする** をオンにします。「認証情報の保護」で、必要に応じてパスキーによる保護も選択します。
4. 保存すると、パスキーによる保護を選択している場合は登録を行い、その後、自動でAPIへの接続を試みます。接続に失敗しても大学アカウント情報は保存されます。設定画面の **APIに接続** から再試行できます。
5. 通常どおり [ScombZ](https://scombz.shibaura-it.ac.jp/portal/home) にアクセスします。セッションが切れた場合は自動復旧を試みます。

初期設定後も、APIログイン設定がオンの場合は、大学アカウントの保存後に自動でAPIへの接続を試みます。

学番を変更するときは、大学ユーザー名と大学パスワードを入力して「大学アカウントを保存」を押してください。未保存の別アカウントではAPIへ接続できません。

認証経路は大学のMobile APIとOTKEYブリッジを利用します。


### パスキーによる認証情報の保護

「認証情報の保護」の「パスキーで認証情報を保護する」を有効にすると、この端末に保存するTOTPシード・大学パスワード・APIトークンをパスキーで保護します。ScombZ自動ログインを使わない場合も利用でき、ScombZの自動ログイン・SESSION再認証とAPI接続の前にも本人確認します。初期状態では無効です。

バックアップファイルはパスキーでは保護されません。ファイルも保護する場合は、「バックアップ」でバックアップパスワードによる暗号化を選択してください。

設定画面を開いたまま解除の有効期限が切れた場合は、操作時にパスキー解除画面へ切り替わります。「パスキーで解除」から再認証すると、ページを再読み込みせずに設定を続けられます。

Android Chromeではパスキーを生成できない場合があります。

パスキーを失うと保管庫を復号できないため、大学アカウント・TOTPシードなどを安全に再設定できるよう備えてください。保管庫の「すべて削除」は復号できない場合も実行できますが、データは復元できません。


パスキー設定はバックアップに含まれません。鍵を失った場合は拡張機能の設定をリセットし、認証情報を再設定してください。

### マスターパスワードからパスキーへの移行

保管庫をマスターパスワードで保護する機能は廃止し、パスキーによる保護へ移行します。新しいマスターパスワードは設定しません。

1. これまで利用していたブラウザープロファイルで拡張機能を更新し、設定画面を開きます。利用前の確認に同意します。
2. 「マスターパスワードからパスキーへ移行」で、これまで設定していた**マスターパスワード**を入力します。
3. 「解除してパスキーを登録」を押して、パスキーを登録します。解除済みのセッションが残っている場合は、マスターパスワードの再入力なしで登録へ進めます。
4. 登録が完了すると、保存済みの大学アカウント・TOTPシード・設定を引き継いでパスキーで暗号化します。以後、保管庫の解除にはパスキーを使います。

パスキー登録をキャンセルした場合や対応していない環境では、元のマスターパスワード保護を保持し、移行は完了しません。設定画面から再試行できます。移行完了前にブラウザーを再起動した場合は、マスターパスワードを再入力してください。

マスターパスワード保護を無効にしていた場合は、端末キー方式のデータを引き継ぎます。パスキーを利用する場合は、「認証情報の保護」でパスキーによる保護を有効にしてください。


## 認証情報・バックアップ

大学パスワード、Bearer Token、TOTPシードはAES-GCMで暗号化してブラウザー内に保存されます。

**大学パスワード・APIトークン・パスキー設定はバックアップに含めません。** バックアップには大学ユーザー名・設定・TOTPシードが含まれます。

設定画面では「バックアップ」→「バックアップをインポート」→「データ削除」の順に表示されます。

- 暗号化する場合は「バックアップパスワードで暗号化する」をオンにし、8文字以上の**バックアップパスワード**と確認用パスワードを入力します。バックアップパスワードを忘れると復元できません。
- 暗号化しない場合、TOTPシードは平文で出力されます。ファイルは安全な場所に保管してください。
- 復元時は「バックアップをインポート」でファイルを選択します。暗号化バックアップには、作成時に指定したバックアップパスワードが必要です。旧SITのバックアップも同様で、保管庫のマスターパスワードとは別です。

マスターパスワードを忘れた場合は、移行画面の「データを削除して再設定」から確認後にリセットできます。削除したデータは戻せませんが、保管してあるバックアップからシードと設定を復元できます。

復元時はADFSとScombZの自動ログインがオフになります。大学パスワードを保存し、必要な自動ログイン設定をオンにしてScombApp APIへ再接続してください。新しい端末でパスキーを利用する場合も別途設定が必要です。

## ADFS・TOTP

<details>
<summary>Microsoft 365向けADFSの自動入力、TOTPシード抽出、コード生成の手順を表示</summary>

**ADFSのID・パスワード自動入力、MFA選択、TOTP自動入力は初期状態ではオフです。**

#### 1. Microsoftアカウントのサインイン方法を変更する

1. [セキュリティ情報](https://mysignins.microsoft.com/security-info)にアクセスします。
2. 「最も適したものが利用できない場合のサインイン方法」を、`Authenticator アプリまたはハードウェア トークン - コード` に変更します。

#### 2. Microsoft Authenticatorを登録する

root化済みのAndroid端末、またはrootを利用できるAndroid EmulatorにMicrosoft Authenticatorをインストールし、大学アカウントを登録します。

Android EmulatorではQRコードを読み取れないため、登録画面で `Can't scan the QR code?` を選択し、表示された情報をテキストで入力してください。

#### 3. Pythonをインストールする

Pythonがインストールされていない場合はPython 3をインストールします。

Windowsでは、PowerShellまたはコマンドプロンプトからwingetを使用できます。

```powershell
winget install --id Python.Python -e
```

インストール後、次のコマンドでPythonが利用できることを確認してください。

```bash
python --version
```

#### 4. TOTPシードを取り出す

Microsoft Authenticatorのデータベース `PhoneFactor`、`PhoneFactor-wal`、`PhoneFactor-shm`を、`tools/extract_phonefactor_seed.py` と同じディレクトリに配置します。

Android上の保存場所は次のとおりです。

```text
/data/user/0/com.azure.authenticator/databases/PhoneFactor
```

リポジトリのルートディレクトリで、次のコマンドを実行します。

```bash
python tools/extract_phonefactor_seed.py
```

出力された `oath_secret_key` のうち、自分の大学アカウントに対応する32文字の英数字がTOTPシードです。

> [!CAUTION]
> TOTPシードは認証コードを生成できる秘密情報です。第三者への送信、画面共有、Issueへの投稿、ソースコードへの記載など、外部への公開は絶対にしないでください。

#### 5. 拡張機能を設定する

1. 使用するブラウザー向けの拡張機能をインストールします。ソースコードから利用する場合は、後述の「ビルド」を参照してください。
2. 拡張機能の設定画面を開きます。
3. TOTPコードを使う場合はシードを入力します（ScombZのみ使う場合は省略可能）。
4. 初期設定を保存します。初期設定後はADFS設定の各チェックボックスは自動保存されます。TOTPシードは専用の保存ボタンから更新できます。初期設定時にシードの保存が完了すると、パスキー登録やAPI接続の成否にかかわらずコード確認画面が表示されます。

#### ADFSログイン・認証コード設定を有効にする場合

初期設定および設定画面で「ADFSログイン・認証コード設定(非推奨)」を開き、TOTPシードやADFS自動ログイン・TOTP自動入力に必要な項目だけ設定します。通常は折りたたまれた状態です。TOTPシードの有無にかかわらず大学ユーザー名と大学アカウントのパスワードは必須です。

### 画面変更の診断

ADFSページで既知のログイン画面、MFA選択画面、TOTP入力画面のいずれも認識できない状態が4秒以上続くと、画面右下に診断パネルを表示します。

「診断情報をコピー」を押すと、拡張機能のバージョン、URLのパス、検出した要素IDなどをコピーできます。入力値、TOTPシード、大学パスワード、URLのクエリ文字列は含みません。

## トラブルシューティング

- **API接続できない**：大学ユーザー名・大学パスワードを確認して「APIに接続」を実行してください。
- **ScombZログイン画面から戻れない**：API接続状態を確認し、ログイン画面を再読み込みしてください。失敗時は大学の通常ログインを利用できます。
- **旧版のエラーが残る**：拡張機能の管理画面から最新版を再読み込みしてください。
- Issue等にパスワード、Bearer Token、OTKEY、SESSION、TOTPシードを投稿しないでください。

## 必要環境

- Node.js 24以上（24 LTSを推奨）
- npm（Node.jsに同梱）

外部npmパッケージは使用しません。`npm install` は不要です。

## 検証

```bash
npm run check
```

`manifest.json`、参照ファイル、JavaScript構文を検証し、ScombZ API接続・OTKEY転送の回帰テストを実行します。

## ビルド

Chromium版とFirefox版をまとめて生成します。

```bash
npm run build
```

生成先は次のとおりです。

```text
dist/chromium/  Chrome、EdgeなどのChromium系ブラウザー向け
dist/firefox/   Firefox向け
```

個別に生成する場合は、次のコマンドを使用します。

```bash
npm run build:chromium
npm run build:firefox
```

Chromium版は、ChromeまたはEdgeの拡張機能管理画面でデベロッパーモードを有効にし、「パッケージ化されていない拡張機能を読み込む」から `dist/chromium/` を指定します。

Firefox版は `about:debugging#/runtime/this-firefox` を開き、「一時的なアドオンを読み込む」から `dist/firefox/manifest.json` を指定します。

Firefox版では、ビルド時にバックグラウンド処理をFirefox向けに変換し、WebExtensions APIの名前空間を `browser` に置き換えます。ChromeとEdgeは同じChromium版を使用します。

## 配布用ZIPの生成

npm run package
```

`release/` に次の配布ファイルを生成します。

scombz-login-helper-chromium.zip
scombz-login-helper-firefox.zip
```

## セキュリティ上の注意

TOTPシード、大学アカウント情報、Mobile API Bearer TokenをAES-GCMで暗号化してブラウザーのローカルストレージに保存します。

パスキーによる保護が無効の場合は、端末のランダムなキーを使用します。自動解除キーもブラウザープロファイル内にあるため、そのプロファイルを操作できる第三者への保護にはなりません。

パスキーによる保護を有効にすると、WebAuthn PRFの出力から導出したキーで保管庫を暗号化し、端末の自動解除キーを削除します。解除後の復号キーは5分間、ブラウザーのセッションストレージに保持します。従来のパスキー設定が残っている場合は、「既存パスキーをPRF保護へ移行」から暗号化方式を移行できます。

平文バックアップ内のTOTPシードを含む認証情報を、ソースコード・Issue・ログへ記載しないでください。
